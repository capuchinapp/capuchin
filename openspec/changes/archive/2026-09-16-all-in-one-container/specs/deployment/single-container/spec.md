## Purpose

Предоставляет единый self-hosted способ развёртывания приложения Capuchin в одном Docker-контейнере, где бэкенд, фронтенд и SQLite живут вместе и обслуживаются на одном порту.

## ADDED Requirements

### Requirement: Единый all-in-one Docker-образ

Система SHALL предоставлять один Dockerfile, из которого собирается единый образ, содержащий бэкенд, фронтенд и SQLite хранилище.

#### Scenario: Сборка образа из одного Dockerfile

- **WHEN** выполняется сборка Docker-образа на основе единого Dockerfile в каталоге `build/`
- **THEN** в образе присутствуют скомпилированный бэкенд и собранная статика фронтенда

#### Scenario: Единая точка сборки образа

- **WHEN** вызывается команда сборки Docker-образа
- **THEN** сборка использует один Dockerfile без отдельных файлов для бэкенда и фронтенда

### Requirement: Раздача статики фронтенда Go-приложением

Система SHALL раздавать статику фронтенда самим Go-приложением через встроенную файловую систему (embed FS).

#### Scenario: Запрос к статике фронтенда

- **WHEN** клиент обращается к веб-интерфейсу приложения
- **THEN** Go-приложение отдаёт статические файлы фронтенда из встроенной файловой системы

#### Scenario: Обработка SPA-маршрутов

- **WHEN** клиент запрашивает неизвестный путь, соответствующий клиентскому маршруту фронтенда
- **THEN** приложение возвращает индексный HTML-файл фронтенда

### Requirement: Обслуживание API и фронтенда на одном порту

Система SHALL обслуживать HTTP API и статику фронтенда на одном и том же порту.

#### Scenario: Доступ к API и фронтенду по одному порту

- **WHEN** клиент отправляет запрос к API-эндпоинту или к статике фронтенда на единый сконфигурированный порт
- **THEN** оба типа запросов обрабатываются одним портом без необходимости указывать разные порты

### Requirement: Единый compose.yaml для self-hosted развёртывания

Система SHALL предоставлять файл `deploy/compose.yaml`, описывающий один сервис на основе all-in-one образа.

#### Scenario: Запуск приложения через compose

- **WHEN** пользователь выполняет `docker compose up -d` в каталоге `deploy/`
- **THEN** запускается один контейнер с приложением, обслуживающим API и фронтенд на одном порту

#### Scenario: Отсутствие отдельных сервисов для фронтенда

- **WHEN** пользователь просматривает сервисы композа
- **THEN** в compose.yaml присутствует только один сервис приложения без отдельного nginx-контейнера для раздачи фронтенда

### Requirement: Хранение данных SQLite в single-container развёртывании

Система SHALL хранить базу данных SQLite на постоянном томе при развёртывании через compose.

#### Scenario: Переживание перезапуска контейнера

- **WHEN** контейнер останавливается и запускается заново
- **THEN** данные SQLite сохраняются благодаря подключённому постоянному тому

### Requirement: Отсутствие blue-green deployment

Система SHALL не использовать и не документировать blue-green deployment, так как два одновременно пишущих процесса в одну базу SQLite недопустимы.

#### Scenario: Отсутствие сценария blue-green в README

- **WHEN** пользователь читает README проекта
- **THEN** в README отсутствует описание blue-green deployment

#### Scenario: Обновление запущенного приложения

- **WHEN** пользователь обновляет развёрнутое приложение на новую версию образа
- **THEN** обновление выполняется пересозданием единственного контейнера без запуска параллельной пишущей копии приложения

### Requirement: Обновлённый обратный прокси для all-in-one образа

Система SHALL предоставлять обновлённую конфигурацию nginx для выставления приложения в интернет через единый порт.

#### Scenario: Проксирование запросов к единому порту

- **WHEN** внешний запрос приходит к обратному прокси
- **THEN** обратный прокси направляет запрос на единый порт all-in-one приложения

### Requirement: Сборка единого образа в CI/CD

Пайплайн CI/CD SHALL собирать один all-in-one образ вместо двух отдельных образов бэкенда и фронтенда.

#### Scenario: Сборка образа после изменения кода

- **WHEN** CI/CD workflow выполняется на изменения в репозитории
- **THEN** он собирает и публикует один all-in-one Docker-образ без отдельных сборок для бэкенда и фронтенда
